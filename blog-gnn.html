Understanding Graph Neural Networks for Traffic Anomaly Detection

A practical introduction to graph representations, GCN autoencoders, anomaly scores, and evaluation.

Why model network traffic as a graph?

Traditional machine learning often represents each record as an independent row of features. Network activity is different: connections between devices, flows, and endpoints can contain important context.

Graph learning offers a way to represent entities as nodes and their relationships as edges. A graph neural network can use information from connected neighbors when learning representations.

What a graph convolution does

A graph convolutional network (GCN) updates node representations using their own features and information from neighboring nodes. Stacking layers lets information travel farther through the graph, though deeper models introduce their own tradeoffs.

In my academic network anomaly detection project, the model design uses a two-layer GCNConv encoder with a hidden dimension of 64. The work uses network-security data from NF-UNSW-NB15-v3.

Why use an autoencoder?

An autoencoder learns a compact representation and attempts to reconstruct information from it. When a traffic pattern is unlike the patterns learned during training, reconstruction error may be higher.

That error can become an anomaly score. However, high reconstruction error is not proof of an attack: unusual but legitimate behavior can also trigger an alert.

Thresholds and false alarms

An anomaly score becomes a classification only after choosing a decision threshold. The project uses a 95th-percentile threshold as a way to flag higher-scoring traffic.

Changing the threshold affects the balance between detecting anomalies and generating false positives. Threshold selection should be evaluated on appropriate data rather than treated as universally correct.

How to evaluate the results

Accuracy alone can be misleading when anomalies are rare. Precision asks how many flagged records are actually anomalous; recall asks how many actual anomalies were found.

F1 combines precision and recall, while PR-AUC summarizes precision–recall behavior across thresholds. These metrics help compare approaches, but results depend on the dataset and evaluation setup. No numeric scores are reported here because verified experimental outputs were not provided.

What I would explore next

A useful next step is to compare graph-based detection with a simpler baseline and analyze false positives. I would also examine how graph construction, feature choices, and threshold selection affect performance.

The most important lesson is that a model architecture is only one part of a reliable machine learning system: data representation and evaluation matter just as much.
